| 项目 | 内容 |
| --- | --- |
| 版本 / 日期 | v0.1 / 2026-10-17 |
| 状态 | 主要类与接口契约草案，不是已经实现的头文件 |
| 总览 | [模块解耦与依赖设计](./模块解耦与依赖设计.md) |
| 其他模块 | [测试回放与AI接口设计](./测试回放与AI接口设计.md) |

本文覆盖 M01–M10。表格给出主要类、初始化参数、成员状态、函数参数和返回语义。标准容器写出元素类型；项目自定义返回结构在正文定义。未列出的构造、析构和普通只读访问器不表示禁止实现，但不得扩大模块职责。

参数约定：`const T&` 和 span 是调用期借用，不能保留给异步任务；传值表示拷贝或转移所有权；注入的组件引用必须比使用它的对象活得更久。构造参数在组合入口先完成校验，不能创建半初始化对象。网络和文件读取返回的值对象拥有自己的数据。

## 1. M01 基础类型与统一错误

### 1.1 类型约定

| 类型 | 表达与用途 |
| --- | --- |
| `PlayerId / SessionId / RoomId / MatchId / ActionId / RunId` | 各自独立的强类型 ID；不能相互隐式转换；网络表示为字符串 |
| `ConnectionId` | 传输生成的本地连接 ID，含代际信息；不能等同于玩家 ID，不在连接生命周期内复用 |
| `Tick / InputSeq / SnapshotSeq / Epoch` | 不同的无符号 64 位强类型；线上用十进制字符串；溢出前拒绝继续使用，不能回绕 |
| `MonoTime` | 单调时钟时间点，用于超时；不作为 UTC 时间展示 |
| `Duration` | 纳秒时长；参数名或格式字段声明单位；与 Tick 不混用 |
| `Bytes / ByteView` | `vector<byte>` / `span<const byte>`；前者拥有数据，后者只在当前调用有效 |
| `Vec2` | `float x, y`，单位为地图世界单位；拒绝 NaN/Infinity；线上按数值序列化 |
| `SecretToken / TokenDigest` | 不可普通打印、不可自动 JSON 序列化的凭证/摘要类型；凭证仅允许在专用握手字段使用 |
| `Error` | `code: ErrorCode`、`message: string`、`field: optional<string>`；message 脱敏并限制长度 |

`ErrorCode` 至少包括：`InvalidArgument`、`InvalidState`、`ProtocolMismatch`、`MalformedPacket`、`Unauthorized`、`NotFound`、`AlreadyExists`、`RoomFull`、`StaleMatch`、`StaleEpoch`、`Expired`、`SequenceGap`、`RateLimited`、`QueueFull`、`WouldBlock`、`Timeout`、`Unsupported`、`IoError`、`CorruptArtifact`、`IncompleteEvidence`、`Cancelled`、`InternalError`。

### 1.2 `Result<T>`

首版 C++20 使用项目定义的 `Result<T>`，不依赖 C++23 的 `std::expected`。它表示成功值或 Error；`Result<void>` 表示成功或 Error。

| 函数 | 参数说明 | 返回值 |
| --- | --- | --- |
| `bool ok() const noexcept` | 无 | 是否成功；不隐式转换为 bool |
| `const T* value_if() const noexcept` | 无；仅 `T != void` | 成功值的借用指针；失败返回 nullptr |
| `const Error* error_if() const noexcept` | 无 | 失败时借用错误；成功返回 nullptr |

正常业务拒绝使用 Error 或明确的 Disposition；不以异常、魔法整数、空字符串或“默认成功对象”表达失败。内存耗尽等不可恢复错误由进程顶层处理，不能伪装成成功。

### 1.3 `IClock` / `SteadyClock`

`IClock` 无可变游戏状态，供应用和测试注入。`SteadyClock` 使用系统单调时间实现；测试可实现 `ManualClock`。

| 函数 | 参数说明 | 返回值 |
| --- | --- | --- |
| `MonoTime now() const noexcept` | 无 | 当前单调时间；不会倒退 |

## 2. M02 数据契约与端口

### 2.1 核心 DTO

以下 DTO 只能通过副本或只读引用跨模块传递，不包含引擎节点、Socket 句柄、可变领域对象指针。跨模块使用的运行结果、证据引用、回放帧等 DTO 也归 M02 的契约文件所有；后文在相关模块旁描述字段只是为便于阅读，不表示报告模块必须导入测试执行器。Python 的场景专用类型与纯校验器放在 M11 的 scenario_contract 子包。

| 结构 | 主要字段及含义 |
| --- | --- |
| `Endpoint` | `host: string`、`port: uint16_t` |
| `PlayerProfile` | `id: PlayerId`、`display_name: string`；ID 来源于服务器，名称不是授权依据 |
| `ActorContext` | `player_id`、`session_id`、`epoch`、`connection_id`；由 SessionService 生成，不能从客户端直接反序列化 |
| `InputFrame` | `match_id`、`epoch`、`seq: InputSeq`、`direction: Vec2`；每帧代表一个固定步长，不接受客户端指定 dt |
| `PickupCommand` | `match_id`、`epoch`、`action_id: ActionId`、`input_seq: InputSeq`、`coin_id: uint32_t` |
| `MoveState` | `position: Vec2`、`velocity: Vec2` |
| `MapDefinition` | `map_id: string`、`revision: uint32_t`、`bounds: Rect`、`obstacles: vector<Rect>`、`spawn_points: vector<Vec2>`；Rect 为有限值的轴对齐矩形 |
| `MovementConfig` | `speed: float`、`player_radius: float`、`tick_hz: uint32_t`；初版建议 4 世界单位/秒、0.3 世界单位、30 Hz，须经玩法验证 |
| `PlayerState` | `player_id`、`move: MoveState`、`score: uint32_t`、`connected: bool` |
| `CoinState` | `coin_id`、`position`、`active: bool` |
| `AckState` | `epoch`、`terminal_input_seq: InputSeq`；水位之前输入均已执行或明确丢弃，不能解释为全部成功执行 |
| `MatchSnapshot` | `match_id`、`tick`、`snapshot_seq`、`players: vector<PlayerState>`、`coins: vector<CoinState>`、`remaining_ticks`、`phase`、`self_ack: optional<AckState>` |
| `MemberView` | `profile`、`ready`、`connected`、`is_host`、`join_order: uint64_t`、`reserve_until: optional<MonoTime>`；线上保留时长用相对毫秒，不能发送本机时间点 |
| `RoomView` | `room_id`、`match_id`、`phase`、`revision: uint64_t`、`members: vector<MemberView>` |
| `MatchResult` | `match_id`、`reason: TimeUp/CoinsExhausted/Aborted`、`scores: vector<PlayerScore>`、`winners: vector<PlayerId>`；PlayerScore 为玩家 ID 与得分 |
| `GameEvent` | `event_id`、`match_id`、`tick`、`kind`、`player_id: optional<PlayerId>`、`payload`；payload 是封闭的事件联合类型，不是任意可执行表达式 |
| `TraceRecord` | `run_id`、`source_id`、`source_seq`、`monotonic_offset_ns`、`match_id/tick` 可选、`body`；body 为脱敏事件、快照、指标或客户端遥测的联合类型 |

`phase` 固定为 WAITING/RUNNING/FINISHED/CLOSED。所有 vector、字符串和消息有上限；配置由启动校验器验证，禁止从网络包直接扩展容量。

### 2.2 消息信封

`Envelope`：`protocol_version: uint16_t`、`kind: MessageKind`、`request_id: string`、`session_id/epoch/match_id` 按消息类型可选、`payload: MessagePayload`。

`MessagePayload` 包括：

| 方向 | 消息与主要内容 |
| --- | --- |
| 客户端 → 服务端 | `Hello{version,display_name}`、`Resume{session_id,token,match_id}`、`CreateRoom{}`、`JoinRoom{room_id}`、`SetReady{ready}`、`StartMatch{}`、`LeaveRoom{}` |
| 客户端 → 服务端 | `Move{InputFrame}`、`Pickup{PickupCommand}`、`Heartbeat{nonce}`、`RequestFullSnapshot{}` |
| 服务端 → 客户端 | `Welcome{identity,epoch,recovery_token?}`、`RoomUpdate{RoomView}`、`MatchStarted{map,rules,snapshot}` |
| 服务端 → 客户端 | `Snapshot{MatchSnapshot}`、`ResumeState{room,map?,rules?,snapshot?,result?}`、`ActionResult{action_id,status,score?}`、`MatchEnded{MatchResult}`、`Pong{nonce}`、`ErrorReply{Error}` |

`identity` 为玩家/会话 ID 的公开值，`rules` 为客户端所需的移动配置、时长和拾取距离。服务器地图和比赛配置来自受信任的启动配置，普通 CreateRoom 消息不能携带测试特权参数。

ResumeState 在 WAITING 时只有房间成员状态；RUNNING 时必须包含 map/rules/snapshot；FINISHED 时还必须包含 result。协议校验器检查这种阶段相关的必填关系，不能仅因为字段标为可选就允许缺少恢复所需数据。

### 2.3 `ITransport`

此端口由 M02 定义，M04 实现。`Channel` 取 Control/Input/Snapshot；通道可靠性在总览中固定。

| 函数签名 | 参数及行为 | 成功返回 / 失败 |
| --- | --- | --- |
| `Result<void> listen(const Endpoint& local)` | 绑定服务端地址；仅初始化时调用 | 成功开始监听；端口占用为 IoError |
| `Result<ConnectionId> connect(const Endpoint& remote)` | 异步发起连接，不等待完成 | 本地连接 ID；实际完成由事件通知 |
| `Result<vector<TransportEvent>> poll(size_t max_events, Duration budget)` | 非阻塞轮询，限制事件数及本轮时间 | 事件列表；无事件返回空列表 |
| `Result<SendReceipt> send(ConnectionId id, Channel channel, ByteView bytes)` | 调用结束前复制或接管发送数据；校验大小 | `SendReceipt{queued_bytes}`；队列满为 QueueFull，未知连接为 NotFound |
| `Result<void> close(ConnectionId id, CloseReason reason)` | 请求关闭连接；已经关闭时幂等成功 | 不代表对端已收到关闭通知 |
| `optional<TransportStats> stats(ConnectionId id) const` | 读取底层测量值 | 统计或 nullopt；缺失指标保持 optional |

`TransportEvent` 是 `Connected{id}`、`Received{id,channel,bytes}`、`Disconnected{id,reason}`、`ConnectFailed{id,error}` 的联合。`TransportStats` 包含可选 RTT、收发字节、待发队列长度；未知丢包率不能填 0。

### 2.4 `ITraceSink` 与 `ITokenProvider`

| 接口函数 | 参数及行为 | 返回值 |
| --- | --- | --- |
| `EnqueueStatus ITraceSink::try_append(TraceRecord record)` | 传值，接收后拥有副本；非阻塞 | Accepted / Full / Closed；Full 必须标记证据不完整 |
| `Result<SecretToken> ITokenProvider::issue()` | 通过受信任随机来源生成凭证 | 新凭证；随机源失败为 InternalError |
| `TokenDigest ITokenProvider::digest(const SecretToken& token)` | 不暴露原始凭证 | 用于存储的摘要 |
| `bool ITokenProvider::matches(const SecretToken& token, const TokenDigest& expected)` | 使用经过验证的密码学实现比较，不能自创算法 | 是否匹配 |

凭证具体算法和实现由适配器选择并在依赖验证中记录。业务模块只依赖此端口，测试可注入固定提供者。

## 3. M03 协议编解码

### `ProtocolCodec`

初始化参数为 `CodecLimits`：`max_packet_bytes=16384`、`max_name_bytes=48`、`max_request_id_bytes=64`、`max_obstacles=32`、`max_players=4`、`max_coins=64`。这些是首版设计限额，调整需同步 Schema 和边界测试。

| 函数签名 | 参数及行为 | 返回值 |
| --- | --- | --- |
| `Result<Envelope> decode(ByteView bytes, Direction direction) const` | 先限字节数，再解析类型和字段；direction 限制消息方向 | 类型化信封；MalformedPacket / ProtocolMismatch |
| `Result<Bytes> encode(const Envelope& message, Direction direction) const` | 编码显式字段，检查版本和长度 | 拥有内存的字节；超限或类型错误返回 InvalidArgument |
| `Result<void> validate(const Envelope& message, Direction direction) const` | 只校验结构、枚举、范围及字段存在性 | 不验证身份、房间成员或拾取距离 |

编解码不直接记录完整 payload。敏感字段由调用层在生成 TraceRecord 前剔除。

## 4. M04 传输适配

### `EnetTransport : ITransport`

构造参数：`TransportConfig{role: Server/Client, max_connections=8, max_packet_bytes=16384, max_pending_send_bytes_per_connection=262144, connect_timeout_ms=3000}`。服务端连接上限包含尚未进入房间的连接，不能替代四人房间限制。

主要成员：底层 host、连接 ID 到底层 peer 的私有映射、发送容量计数、底层事件缓存。它们只由所属轮询线程访问。

公开函数完整实现 M02 的 ITransport，不增加“加入房间”“发送玩家位置”等业务函数。只在本适配器文件中包含 ENet 头文件；上层不能引用底层 peer 类型。构造、停止、重建及通道映射须由互通验证覆盖。

## 5. M05 会话服务

### `SessionService`

构造：`SessionService(SessionConfig config, ITokenProvider& tokens)`。`SessionConfig` 含 `idle_timeout=3s`、`resume_grace=10s`、`max_sessions=16`。tokens 为借用依赖，由入口持有。

主要成员：会话表、当前连接索引、玩家索引、凭证摘要、epoch、最后有效流量时间、固定恢复截止时间和可恢复比赛范围。仅逻辑线程修改。

| 函数签名 | 参数及行为 | 成功返回 / 失败 |
| --- | --- | --- |
| `Result<SessionGrant> create(ConnectionId conn, string display_name, MonoTime now)` | 建立访客，生成服务器身份和凭证 | grant；同连接已有身份为 AlreadyExists，容量满为 RateLimited |
| `Result<ActorContext> authenticate(ConnectionId conn, SessionId claimed_session, Epoch claimed_epoch, MonoTime now)` | 校验绑定；只有校验通过才更新有效流量时间 | 可信 ActorContext；Unauthorized / StaleEpoch |
| `Result<void> bind_scope(PlayerId player, MatchId match)` | 加入房间成功后设置可恢复的比赛 | 未知玩家为 NotFound |
| `Result<SessionGrant> resume(ConnectionId conn, const ResumeRequest& request, MonoTime now)` | 验证凭证、比赛范围、截止时间，原子替换连接并递增 epoch | grant 含旧连接 ID；Unauthorized / Expired / StaleMatch |
| `optional<SessionTransition> disconnected(ConnectionId conn, MonoTime now)` | 仅当前有效连接可触发断线；第一次判定固定截止时间 | 当前身份的 Disconnected 转换；迟到旧连接事件返回 nullopt |
| `vector<SessionTransition> expire(MonoTime now)` | 判定空闲和恢复过期，每个转换只发出一次 | IdleDisconnected / RecoveryExpired 事件列表 |
| `Result<void> invalidate_scope(PlayerId player, MatchId match)` | 离房/关房后取消旧局恢复权限，但可保留在线访客身份 | 不存在的对应范围视为已失效，幂等成功 |

`SessionGrant{actor: ActorContext, recovery_token: optional<SecretToken>, replaced_connection: optional<ConnectionId>}` 不得整体记录。`ResumeRequest{session_id, token, match_id}`。`SessionTransition{kind,player_id,epoch,connection_id,deadline,match_id?}` 仅含公开标识，不含凭证。

新访客签发恢复凭证；首版恢复时沿用原凭证，不做缺少确认机制的单边凭证轮换，因此恢复 grant 不再次携带凭证。恢复资格仍受比赛范围和截止时间约束；过期转换发出后清理失效会话索引。已经在线的会话仅在其有效比赛范围内允许凭证持有者替换连接；断线后的恢复截止时间不能被尝试恢复延长。

ServerApp 在同一逻辑线程完成 resume 和 Room 恢复协调；房间已关闭时先失效恢复范围。若会话恢复成功后发现比赛已不可恢复，应返回 StaleMatch 并失效该范围，不得重建旧局或补发分数。

## 6. M06 共享移动计算

### `MovementModel`

构造：`MovementModel(MapDefinition map, MovementConfig config)`，持有只读地图和参数。首版使用简单静态碰撞，不调用 Godot 物理引擎。服务器和原生客户端使用相同计算代码；不承诺跨架构位级确定性。

| 函数签名 | 参数及行为 | 返回值 |
| --- | --- | --- |
| `Result<Vec2> normalize_intent(Vec2 direction) const` | 检查有限值，长度超过 1 时限幅 | 合法方向；非有限数为 InvalidArgument |
| `MoveState step(const MoveState& current, Vec2 normalized_direction) const` | 使用固定 `1/tick_hz` 步长、速度及静态碰撞；前置条件为输入已验证 | 新位置和速度，不修改 current |
| `bool can_pickup(Vec2 player_pos, Vec2 coin_pos, float pickup_radius) const` | 基于相同坐标系检查距离 | 是否在范围；是否真能领取仍由 MatchSimulation 决定 |
| `bool valid_position(Vec2 position) const` | 检查边界和静态障碍 | 是否允许作为角色中心 |

`step` 对合法输入不产生业务失败；地图/速度/半径的不合法组合在启动配置校验阶段拒绝。

## 7. M07 游戏领域

### 7.1 `InputBuffer`

构造：`InputBuffer(InputPolicy policy)`。`InputPolicy{capacity_per_player=32, max_age_ticks=6, max_frames_per_player_per_tick=1}`。拥有当前比赛/玩家/epoch 的输入队列和终结水位；不访问连接和时钟。

| 函数签名 | 参数及行为 | 返回值 |
| --- | --- | --- |
| `Result<InputAdmission> push(PlayerId player, const InputFrame& frame, Tick received_tick)` | 连续序号入队；已见序号为重复；可靠输入出现跳号则拒绝 | Queued / Duplicate；SequenceGap / QueueFull / StaleEpoch |
| `InputSelection take(PlayerId player, Tick tick)` | 丢弃在队列等待超过 6 Tick 的输入，最多取 1 帧；没有输入则本帧中性方向 | `frame?`、`ack: AckState`、`dropped: vector<InputDrop>` |
| `void reset(PlayerId player, MatchId match, Epoch epoch)` | 新局或恢复时清空旧队列，序号从 1 开始 | 无返回值 |
| `void erase(PlayerId player)` | 移除玩家队列，重复操作安全 | 无返回值 |

`InputAdmission{disposition,seq}`；`InputDrop{seq,reason}`。Ack 仅在输入实际执行或被明确终结后前移。重复已排队输入不会占用新容量；队列满或跳号时应用层要求恢复连接以建立新 epoch，不跳过缺口后假称已执行。

### 7.2 `MatchSimulation`

构造：`MatchSimulation(MatchConfig config, vector<PlayerProfile> players, MovementModel movement)`。

`MatchConfig`：`match_id`、`duration_ticks=1800`、`initial_coins: vector<CoinState>`、`pickup_radius`（初始建议 0.6 世界单位）、`max_actions_per_player=1024`、`max_pickups_per_second=10`、`seed: uint64_t`。地图和出生点由 Room 启动时验证；seed 记录初始化选择，不代表全网络确定性。

主要成员：局内 Tick、玩家状态、金币状态、动作结果缓存、剩余时间和可选最终结果。

| 函数签名 | 参数及行为 | 返回值 |
| --- | --- | --- |
| `SimulationFrame step(const vector<PlayerMove>& moves, const vector<AuthorizedPickup>& pickups)` | 先应用本帧移动，再按玩家 ID、input_seq、action_id 排序处理拾取，最后判断结束 | 当前完整状态、事件列表、可选结算；每调用一次推进一个 Tick |
| `Result<ActionOutcome> pickup(const AuthorizedPickup& command)` | 内部规则入口，检查在线、距离、金币状态、速率和 ActionId；可直接用于规则测试 | Applied / Duplicate / Rejected 与稳定业务结果 |
| `Result<void> set_connected(PlayerId player, bool connected)` | 离线时速度归零；恢复不创建重复玩家 | 未知玩家为 NotFound |
| `Result<void> remove_player(PlayerId player)` | 释放实体；事件中保留移除原因和最后得分 | 不存在时幂等成功 |
| `WorldView view() const` | 返回当前状态副本 | `WorldView{match_id,tick,players,coins,remaining_ticks,result?}` |

`PlayerMove{player_id,frame?}`；`AuthorizedPickup{actor_player_id,command: PickupCommand}` 由应用层绑定身份。`SimulationFrame{world: WorldView,events: vector<GameEvent>,result: optional<MatchResult>}`。`ActionOutcome{action_id,disposition,score_after?,error?}`；Rejected 必须带 error。

幂等键为 `(match_id,player_id,action_id)`，恢复连接时不清空。命中缓存返回首次结果且不重发成功领取事件；缓存满时拒绝新的 ActionId，不能通过驱逐旧键导致重复效果。即便使用新 ActionId，已消失金币也不能再次领取。

### 7.3 `Room`

构造：`Room(RoomConfig config)`。`RoomConfig{room_id,match_id,max_players=4,match: MatchConfig,map: MapDefinition,movement: MovementConfig,finished_hold=15s}`。一个 Room 只对应一场比赛；重新开局创建新 Room/MatchId。

主要成员：phase、成员表及加入顺序、房主 ID、InputBuffer、可选 MatchSimulation、待处理拾取列表、有界请求结果缓存、结算展示截止时间。

| 函数签名 | 参数及行为 | 返回值 |
| --- | --- | --- |
| `Result<RoomView> join(PlayerProfile player, Epoch epoch)` | 仅 WAITING，成员去重，保存可信会话 epoch，检查容量，首位成为房主 | 新房间视图；RoomFull / InvalidState |
| `Result<RoomView> set_ready(PlayerId player, bool ready)` | 仅在线成员、WAITING | 新视图；NotFound / InvalidState |
| `Result<FrameOutcome> start(PlayerId requester, MonoTime now)` | 房主发起，至少两人且全部在线准备；创建唯一仿真并初始化各玩家输入 epoch | 初始领域状态；Unauthorized / InvalidState；由同步模块封装网络快照 |
| `Result<InputAdmission> enqueue_move(PlayerId player, const InputFrame& frame)` | RUNNING、在线、匹配比赛/epoch；交给 InputBuffer | 入队结果；不会立即推进游戏 |
| `Result<PickupReceipt> enqueue_pickup(PlayerId player, const PickupCommand& command)` | 校验阶段及容量，排入下一 Tick | Queued / DuplicatePending；最终 ActionOutcome 通过后续事件返回 |
| `FrameOutcome step(MonoTime now)` | RUNNING 时推进一个逻辑 Tick、产生事件；结束则进入 FINISHED | `FrameOutcome{world?,events,acks,result?,phase,phase_changed}` |
| `Result<void> on_disconnect(PlayerId player, Epoch epoch, MonoTime deadline)` | 标为离线、清空未执行输入/拾取、停止移动；截止时间只用于展示 | NotFound / StaleEpoch；不自行生成第二个截止时间 |
| `Result<RestoreView> on_resume(PlayerId player, Epoch new_epoch)` | 更新现有成员 epoch 并重置输入；WAITING 返回成员视图，RUNNING/FINISHED 附领域状态 | 不创建新实体；NotFound / InvalidState；同步模块封装恢复消息 |
| `Result<RoomView> leave(PlayerId player)` | 主动退出直接释放席位；WAITING 转交房主 | 新视图；不存在时返回当前视图，幂等 |
| `Result<void> expire_member(PlayerId player, Epoch expected_epoch)` | 由会话过期转换触发；仍属于该离线 epoch 才释放 | 已恢复的玩家不被误删，返回 StaleEpoch |
| `vector<GameEvent> maintain(MonoTime now)` | FINISHED 到 15 秒关闭；无人可保留时关闭；WAITING 无在线成员时关闭 | 生命周期事件列表，不推进游戏 Tick |
| `RoomView view() const` | 无 | 只读副本；没有开放可变成员表访问器 |
| `FrameOutcome current_frame() const` | 查询当前领域状态，不推进 Tick，不重复发业务事件 | 当前 world/acks/result/phase；events 为空，WAITING 无 world |

`PickupReceipt{action_id,disposition}` 只代表排队状态。`RestoreView{room:RoomView,frame:FrameOutcome}` 为领域恢复数据。FrameOutcome 的 `acks` 为各玩家 AckState 映射；领域不分配网络 SnapshotSeq，该序号只由 SnapshotPublisher 管理。

断线与主动离开语义不同：RUNNING 的网络断线保留席位；主动离开立即释放。WAITING 成员断线时取消准备；WAITING 无在线成员的关闭规则优先于席位保留，关闭后旧局不可恢复。取消尚未执行的拾取须产生取消事件；已经产生效果的 ActionId 缓存不能随断线删除。

## 8. M08 服务端应用与同步

### 8.1 `CommandRouter`

构造：`CommandRouter(SessionService& sessions)`；借用会话服务，不持有 Room 或 Transport。

| 函数签名 | 参数及行为 | 返回值 |
| --- | --- | --- |
| `Result<RoutedCommand> route(ConnectionId conn, const Envelope& message, MonoTime now)` | 握手单独分类；其余消息验证连接、会话和 epoch，绑定可信身份 | `RoutedCommand{actor?,command}`；Unauthorized / StaleEpoch / InvalidArgument |

command 为 Hello/Resume/RoomCommand/Move/Pickup/Heartbeat/RequestFullSnapshot 的封闭联合。route 不执行房间操作，也不接受任意函数名路由。

### 8.2 `TickScheduler`

构造：`TickScheduler(uint32_t hz=30, uint32_t max_catchup_steps=3)`；维护上次更新时间和累计时间。

| 函数签名 | 参数及行为 | 返回值 |
| --- | --- | --- |
| `TickPlan advance(MonoTime now)` | 计算到期步数，最多补 3 步；超出积压截断并计量 | `TickPlan{steps:uint32_t,discarded_wall_time:Duration,next_due:MonoTime}` |

每次 Room.step 仍用固定 dt。持续过载时仿真可能慢于真实时间，必须在报告中暴露，不能通过增大 dt 悄悄跳过规则。

### 8.3 `SnapshotPublisher`

构造：`SnapshotPublisher(uint32_t tick_hz=30, uint32_t snapshot_hz=10)`；校验首版频率整除，维护每场比赛快照序号。

| 函数签名 | 参数及行为 | 返回值 |
| --- | --- | --- |
| `vector<OutboundMessage> build(const FrameOutcome& frame, const vector<Recipient>& recipients, bool force_full)` | 达到周期或强制恢复时，生成面向各玩家的快照与自身 Ack | 类型化待发送消息；不直接操作传输 |
| `void reset(MatchId match)` | 新比赛重建序号空间 | 无返回值 |

`Recipient{connection_id,player_id,epoch}`；`OutboundMessage{connection_id,channel,envelope}`。恢复快照使用 Control 可靠通道；常规快照使用 Snapshot。丢失或发送失败的序号不回收。

### 8.4 `ServerApp`

构造参数：`ServerConfig config, IClock& clock, ITransport& transport, ITraceSink& trace, ITokenProvider& tokens`。拥有 Codec、SessionService、CommandRouter、TickScheduler、SnapshotPublisher 和最多一个 Room；借用基础端口。

`ServerConfig` 汇总前述配置，另有 `network_batch_events=128`、`network_poll_budget=1ms`、`recording_enabled`。启动时检查数值范围及关联条件。

| 函数签名 | 参数及行为 | 返回值 |
| --- | --- | --- |
| `Result<void> start(const Endpoint& local)` | 验证配置并监听；尚未创建游戏房间 | 端口和配置错误明确返回 |
| `Result<PumpStats> pump(MonoTime now)` | 有界网络处理、会话维护、执行到期 Tick、生成回复与快照、投递记录 | 本轮事件数、步数、计算耗时、丢弃/拒绝计数；单条非法请求不会导致整个 pump 失败 |
| `Result<void> handle(const RoutedCommand& command, MonoTime now)` | 应用层分派；协调会话与房间，结果封装为回复 | 调用层将业务拒绝转换为 ErrorReply |
| `Result<void> stop(Duration deadline)` | 停止新请求、关闭房间和连接；记录刷新由组合入口在其后完成 | 成功或 Timeout；操作幂等 |

pump 不执行文件写入和模型请求。不可恢复的监听失败才使其返回失败；记录不完整和单连接超限通过状态/事件报告。创建、加入、准备等控制请求按 `(session,epoch,request_id)` 去重或保持幂等，重复请求不得建出第二个房间。

## 9. M09 客户端核心

### 9.1 `PredictionController`

构造：`PredictionController(MovementModel movement, size_t max_pending_inputs=64)`。持有本地预测状态、当前比赛/epoch 和未终结输入，不能修改权威得分。

| 函数签名 | 参数及行为 | 返回值 |
| --- | --- | --- |
| `Result<MoveState> predict(const InputFrame& frame)` | 为固定步长新输入计算并保存预测；每帧只调用一次 | 新预测状态；缓存满为 QueueFull，触发重新同步 |
| `Result<ReconcileResult> reconcile(const PlayerState& authority, const AckState& ack)` | 删除水位内输入，在权威位置上按序重放剩余输入 | `ReconcileResult{predicted,correction_distance,pending_count}`；StaleEpoch / InvalidArgument |
| `void reset(MatchId match, Epoch epoch, const PlayerState& authority)` | 新局或恢复时清空历史 | 无返回值 |

InputBuffer 丢弃的输入也计入终结水位，因此客户端不会永久重复预测服务器已明确放弃的动作。QueueFull 不能以静默抛弃历史后继续显示“正常同步”处理。

### 9.2 `SnapshotBuffer`

构造：`SnapshotBuffer(size_t max_snapshots=64, uint32_t interpolation_delay_ticks=3)`；持有一个比赛的有序快照副本。

| 函数签名 | 参数及行为 | 返回值 |
| --- | --- | --- |
| `Result<SnapshotDisposition> push(MatchSnapshot snapshot)` | 验证比赛和单调序号；过期快照记录为丢弃，不覆盖当前状态 | Applied / IgnoredOld / IgnoredDuplicate；跨局为 StaleMatch |
| `optional<RenderSample> sample(double render_tick) const` | 在相邻快照间插值；不足两帧时使用最近帧，不无限外推 | `RenderSample{players,from_tick,to_tick,alpha,is_interpolated}`；无数据为 nullopt |
| `void reset(MatchId match)` | 清空旧局缓存 | 无返回值 |

### 9.3 `ClientRuntime`

构造：`ClientRuntime(ClientConfig config, ITransport& transport, ITraceSink& trace)`。`ClientConfig{protocol_version, heartbeat_interval=1s, input_hz=30, max_pending_inputs=64, prediction_enabled=true, interpolation_enabled=true}`。拥有 Codec、连接状态、私有恢复凭证、预测器、快照缓存、待发送输入和业务结果。

| 函数签名 | 参数及行为 | 返回值 |
| --- | --- | --- |
| `Result<void> connect(const Endpoint& endpoint, string display_name)` | 发起异步连接；连接事件后再握手 | 请求被接受；已连接为 InvalidState |
| `Result<string> send_room_command(const RoomRequest& request)` | Create/Join/Ready/Start/Leave 封闭类型，生成 request_id | 请求 ID；业务结果在客户端事件中返回 |
| `Result<void> set_move_intent(Vec2 direction)` | 设置下一固定客户端步长使用的方向，不立即发送任意次数输入 | 非有限方向为 InvalidArgument |
| `Result<InputSeq> submit_move(Vec2 direction)` | 由 update 的 30 Hz 输入采样调用；分配序号、预测并排入本地发送队列 | InputSeq；不能每次渲染无限调用；满队列进入恢复流程 |
| `Result<ActionId> request_pickup(uint32_t coin_id, optional<ActionId> retry_id)` | 无 retry_id 时创建新动作；重试保持同一 ActionId，使用当前 epoch | 动作 ID；最终结果异步返回 |
| `Result<ClientUpdate> update(MonoTime now)` | 非阻塞网络处理、心跳、固定频率采样、预测校正和事件收集 | `ClientUpdate{events,view:ClientView,diagnostics}` |
| `Result<void> resume()` | 使用内存中的凭证和旧比赛请求恢复；成功后重置预测/序号 | 发起恢复；缺凭证或已过期状态为 InvalidState |
| `Result<void> disconnect(bool leave_room)` | true 表示主动离房；false 表示断开但保留服务器恢复资格 | 请求关闭；重复操作幂等 |
| `ClientView view() const` | 无 | 只读展示副本，不含凭证 |

`RoomRequest` 为房间操作联合类型。`ClientEvent` 至少包含 Connected、RoomChanged、MatchStarted、ActionCompleted、Disconnected、Resumed、MatchFinished、Error。`ClientView{connection_state,room?,match?,self_authority?,self_prediction?,render_sample?,result?}`。`ClientDiagnostics` 包含 optional RTT、最新快照 Tick、终结输入水位、待确认数和校正距离。

传输暂时无法入队时保留尚未发送帧，不能先丢帧再发送后续序号；超过容量则显式恢复。恢复后业务重试保持 ActionId，移动 InputSeq 随新 epoch 从 1 重新开始。

## 10. M10 Godot 桥接与表现

### 10.1 `NetArenaBridge`

C++ 原生扩展对 Godot 暴露的唯一在线游戏入口。构造参数为 `NetArenaBridge(ClientRuntime& client)`，只借用客户端核心。具体传输、记录适配器与 ClientRuntime 由独立的原生扩展组合入口创建并持有，比 bridge 活得更久；bridge 本身不直接依赖 M04/M13。边界将前述 C++ DTO 转换为 Godot 可识别类型。

Godot 的所有返回字典统一为 `BridgeResult{ok:bool,data:Variant,error:Dictionary?}`；error 含 code/message/field，不包含凭证。64 位 ID/序号在 Dictionary 中使用字符串。

| 函数签名（Godot 侧） | 参数 | 返回值 |
| --- | --- | --- |
| `connect_server(host: String, port: int, name: String) -> Dictionary` | 连接地址及显示名 | BridgeResult，表示发起状态 |
| `room_action(action: String, args: Dictionary) -> Dictionary` | 白名单 create/join/ready/start/leave；转换为 RoomRequest | BridgeResult，成功 data 含 request_id |
| `set_move_direction(direction: Vector2) -> Dictionary` | 当前输入方向 | BridgeResult；采样频率由 ClientRuntime 控制 |
| `pickup(coin_id: int, retry_action_id: String = "") -> Dictionary` | 金币及可选重试动作 | BridgeResult，data 含 ActionId |
| `poll() -> Dictionary` | 原生层读取单调时钟并调用 update；每渲染帧调用一次 | 展示 DTO 和诊断；不返回内部对象指针 |
| `resume_session() -> Dictionary` | 无；凭证留在原生层 | 发起恢复的 BridgeResult |
| `disconnect_session(leave_room: bool) -> Dictionary` | 区分主动退出和模拟断线 | BridgeResult |

事件通过只读的 `connection_changed`、`room_changed`、`match_changed`、`action_completed`、`error_occurred` 信号发布。信号 payload 是拷贝，不在信号处理回调中重入修改 ClientRuntime；用户操作排到下一轮 poll。

### 10.2 表现类

| 类 / 初始化依赖 | 主要函数 | 参数与返回值 |
| --- | --- | --- |
| `LobbyPresenter(bridge, lobby_view)` | `refresh(view: Dictionary) -> void`；`on_ready(ready: bool) -> void`；`on_start() -> void` | 显示 RoomView；按钮转成 bridge 请求，不本地判断最终开始成功 |
| `ArenaPresenter(bridge, arena_view)` | `collect_input() -> Vector2`；`render(view: Dictionary) -> void` | 采集方向；绘制角色、金币、得分和结算，不写权威状态 |
| `DebugPresenter(debug_view)` | `refresh(diagnostics: Dictionary) -> void` | 绘制权威/预测/显示位置及网络指标；缺失值显示不可用 |

表现类只保存节点引用、选择状态及显示缓存。复杂测试和 AI 生成首版通过 CLI 完成，不额外建设 Web 管理平台。

## 11. 首版需固定的跨模块行为

| 问题 | 一致处理方式 |
| --- | --- |
| 连接与玩家混用 | ConnectionId 只在传输/会话/应用；领域只接收可信 PlayerId |
| 重连后旧输入到达 | epoch 校验先于领域调用；旧断开事件也带连接代际检查 |
| 输入被接受却未执行 | 入队返回 Receipt，真正执行/丢弃更新终结水位并留下原因 |
| 同 Tick 抢金币 | 移动先执行，拾取按 PlayerId、input_seq、ActionId 稳定排序 |
| 高层误认为 send 成功就是游戏成功 | 使用 request_id/ActionId 关联异步业务回复 |
| 预测与碰撞不一致 | 共享 MovementModel；图形表现不得使用另一套物理结果作为权威位置 |
| 发布平台未经验证 | 不标记已支持；同版本适配器、原生扩展和协议夹具一并验证 |
